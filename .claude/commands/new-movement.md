# 새 동작 추가

대상: $ARGUMENTS

발행은 사용자가 관리 화면에서 합니다. 이 커맨드의 목표는
**사용자가 폼에 옮겨 붙이고 발행만 하면 되는 상태**까지 만드는 것입니다.
중간에 되묻지 말고 아래를 끝까지 진행한 뒤 한 번에 보여주세요.

## 1. 기존 형식 확인

`js/data.js` 의 `MOVEMENTS` 항목 하나를 읽어 구조를 그대로 파악합니다.
필드 이름·순서·자료형·`CATEGORIES` 값을 기존과 똑같이 맞춥니다. **추측하지 않습니다.**

`targets`(주요 사용 근육)는 `js/bodymap.js` 의 `MUSCLE_REGIONS` 표에 **이미 있는 이름**을
써야 합니다. 조회는 문자열 완전 일치라서, 표에 없는 이름은 인체 도식에서 조용히 빠지고
태그 목록에만 남습니다. 표에 없는 이름이 꼭 필요하면 그 사실을 보고에 적으세요.

## 2. 초안 작성

`CLAUDE.md` 의 글쓰기 규칙을 따릅니다 — 동작 이름은 한글과 영문을 함께,
단정적인 의학적 주장 금지, 통증 시 중단과 전문가 상담 안내 유지.

사용자가 준 정보가 부족하면 **없는 내용을 지어내지 마세요.**
무엇이 비었는지 목록으로 보여주고, 채울 수 있는 부분만 채웁니다.

## 3. content-reviewer 검토

Task 로 `content-reviewer` 를 부릅니다. 확인 항목:

- 안전성 경고 누락 (경추 부하, 척추 굴곡 등)
- 난이도가 실제 선행 조건과 맞는지
- 치료·교정을 단정하는 표현이 없는지
- `targets` 가 동작과 맞는지, 호흡 방향이 맞는지
- 기존 항목들과 형식이 맞는지 (도입부 길이, 단계 수, 주의·팁 구분)

지적이 나오면 **반영한 뒤** 다음으로 넘어갑니다.

## 4. accessibility 확인

Task 로 `accessibility` 를 부릅니다. 사진 alt 문구를 정합니다.
"사진", "이미지" 같은 알맹이 없는 말은 쓰지 않습니다. 장식이면 비웁니다.

## 5. 발행용 묶음 출력

관리 화면 폼에 그대로 옮길 수 있도록 **필드별로 나눠서** 보여줍니다.
사진·영상 파일은 사용자가 직접 고릅니다 — 어떤 사진이 필요한지 설명만 적어주세요.
사진은 `jpg/png/webp/gif` 만 됩니다. 영상은 유튜브 링크를 받습니다.

## 끝난 뒤

사용자가 발행하면 `/deploy-check` 로 확인합니다.
