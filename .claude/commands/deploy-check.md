# 배포 확인

대상: $ARGUMENTS

## 1. site-ops — 배포가 돌았는지

Task 로 `site-ops` 를 부릅니다.
GitHub Pages 배포 워크플로가 성공했는지, 변경이 `main` 에 올라가 있는지 확인합니다.
브랜치에만 있으면 사이트에 나타나지 않습니다.

**이 환경에서는 `yangjery.github.io` 에 직접 접속할 수 없습니다.**
curl 로 사이트가 살아 있는지 확인하려 하지 마세요.
워크플로 결과로 판단하고, **직접 보지 못했다는 사실을 밝히세요.**

## 2. qa — 내용이 실제로 맞는지

Task 로 `qa` 를 부릅니다. `CLAUDE.md` 의 "확인 방법" 에 있는 헤드리스 브라우저와
node 명령을 씁니다. 확인 항목:

- `js/data.js` 의 `MOVEMENTS` 개수와 목록 화면 카드 수가 맞는지
- `js/admin.js` 에 문법 오류가 없는지
- 대상 동작의 상세 페이지가 뜨는지
- 없는 id 로 열었을 때 (`movement.html?id=없는것`) 제대로 처리되는지
- 사진이 깨지지 않는지, 영상이 있으면 목록 카드에 영상 표시가 붙는지
- `targets` 가 인체 도식에 실제로 칠해지는지 (표에 없는 이름은 조용히 빠집니다)

**코드를 읽고 "괜찮아 보인다"고 하지 않습니다.** 실제로 띄워서 그림을 보고 판단합니다.

## 3. 결과 보고

확인한 것과 **확인하지 못한 것을 나눠서** 보고합니다.
확인하지 못한 것을 통과했다고 말하지 않습니다.

문제가 있으면 고친 담당에게 돌려보냅니다. `qa` 와 `site-ops` 는 고치지 않습니다.
