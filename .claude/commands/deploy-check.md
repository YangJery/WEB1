# 배포 확인

대상: $ARGUMENTS

## 0. tools/check.sh

```bash
./tools/check.sh
```

먼저 돌립니다. 여기서 걸리면 배포를 확인할 것도 없습니다.
**이 스크립트가 보는 항목은 아래 qa 단계에서 다시 보지 마세요.**

## 1. site-ops — 배포가 돌았는지

Task 로 `site-ops` 를 부릅니다.
GitHub Pages 배포 워크플로가 성공했는지, 변경이 `main` 에 올라가 있는지 확인합니다.
브랜치에만 있으면 사이트에 나타나지 않습니다.

**이 환경에서는 `yangjery.github.io` 에 직접 접속할 수 없습니다.**
curl 로 사이트가 살아 있는지 확인하려 하지 마세요.
워크플로 결과로 판단하고, **직접 보지 못했다는 사실을 밝히세요.**

## 2. qa — 눈으로 봐야 하는 것만

`check.sh` 가 통과했다면 개수·문법·도식 표는 이미 확인된 것입니다. `qa` 는
**기계가 못 보는 것만** 봅니다.

- 올린 사진이 실제로 화면에 뜨는지, 잘리거나 비율이 틀어지지 않았는지
- 영상 자리가 제대로 잡히는지
- 새로 올린 동작의 상세 페이지가 다른 동작들과 어색하지 않은지
- 휴대폰 폭에서 무너진 곳이 없는지

동작 하나를 올린 것뿐이라면 그 동작의 상세 페이지 하나만 보면 됩니다.
전체를 다시 훑지 마세요.

**코드를 읽고 "괜찮아 보인다"고 하지 않습니다.** 실제로 띄워서 그림을 보고 판단합니다.

## 3. 결과 보고

확인한 것과 **확인하지 못한 것을 나눠서** 보고합니다.
확인하지 못한 것을 통과했다고 말하지 않습니다.

문제가 있으면 고친 담당에게 돌려보냅니다. `qa` 와 `site-ops` 는 고치지 않습니다.
