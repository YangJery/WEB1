# 기존 동작 수정

대상: $ARGUMENTS

발행은 사용자가 관리 화면에서 합니다.
**`js/data.js` 를 직접 고치지 마세요** — 관리 화면이 이 파일을 통째로 다시 만듭니다.

## 1. 대상 확인

`js/data.js` 에서 해당 동작을 찾아 **현재 내용을 그대로 보여줍니다.**
이름이 애매하면 후보를 나열하고 어느 것인지 확인받습니다. 되묻는 것은 여기서만입니다.

## 2. 수정안 작성

**바뀌는 필드만** 명확히 표시합니다. 고치지 않는 필드는 건드리지 않습니다.
바꾸는 김에 다른 것까지 손대지 마세요.

`targets` 를 바꾼다면 `js/bodymap.js` 의 `MUSCLE_REGIONS` 에 있는 이름인지 확인합니다.

수정 이유가 다른 동작에도 해당되면 (예: 같은 계열 동작들의 주의사항 누락)
그 사실을 **보고에 적되, 함께 고치지는 않습니다.** 사용자가 정할 일입니다.

## 3. content-reviewer 검토

Task 로 `content-reviewer` 를 부릅니다.
수정된 부분이 안전성·표현·근육·호흡 기준에 맞는지, 기존 항목들과 형식이
어긋나지 않는지 봅니다.

## 4. 발행용 묶음 출력

관리 화면에서 **어느 필드를 무엇으로 바꾸면 되는지** 짚어줍니다.
전체를 다시 쓰지 말고 바뀌는 필드만 보여주세요.

## 끝난 뒤

사용자가 발행하면 `/deploy-check` 로 확인합니다.
